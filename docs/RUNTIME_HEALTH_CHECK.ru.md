# Runtime Health Check

Runtime Health Check — это пассивный снимок состояния подсистем Fiximizer. Он доступен из панели управления и также включается в локальный Diagnostic Bundle в виде файла `health.json`.

## Значения состояний

| Состояние | Значение |
|---|---|
| `HEALTHY` | Подсистема инициализирована, опубликованный статус указывает на штатную работу. |
| `DISABLED` | Функция отключена в конфигурации или текущем профиле оптимизации. |
| `DEGRADED` | Возможность недоступна либо подсистема перешла на поддерживаемую резервную реализацию. |
| `UNSUPPORTED` | Текущая среда не предоставляет совместимую возможность для этой необязательной функции. |
| `FAILED` | Инициализация или необходимая операция завершилась ошибкой. Снимок указывает fallback и необходимость действий пользователя. |
| `NOT_STARTED` | Отложенная инициализация или первая выборка ещё не завершилась. |
| `IDLE` | Функция доступна, но сейчас не активна, поскольку условия её запуска не выполнены. |

## Какие подсистемы отображаются

Снимок показывает Startup, Diagnostics, JFR, Memory Guard, Scheduler, Memory Optimizer, Network Telemetry, Java/Rust backend статистики, GPU Telemetry, OpenCL, VRAM cache и необязательные интеграции модов.

Каждая запись содержит постоянный ID подсистемы, состояние, очищенное описание причины, описание fallback, флаг необходимости действий пользователя и время последнего замеченного перехода состояния. Время меняется только при изменении состояния или поясняющих полей.

## Сбор данных и приватность

- Сбор читает только кэшированное или уже опубликованное состояние сервисов. Он не инициализирует GPU/OpenCL, не открывает подключения, не запускает бенчмарки, не читает логи и не выполняет дисковые операции.
- Снимок интерфейса кэшируется на одну секунду, чтобы не повторять сбор при каждом кадре.
- Отсутствующие метрики остаются недоступными: они не превращаются в измеренный ноль.
- Причины очищаются и ограничиваются по длине. Diagnostic Bundle дополнительно применяет текстовый фильтр перед записью `health.json`.
- Список модов, личные данные игрока, адрес сервера, содержимое пакетов и пути файловой системы не включаются.
- Отключённая или неподдерживаемая необязательная подсистема не делает остальные подсистемы неисправными.

Отчёт описывает состояние подсистем, а не гарантирует прирост производительности. Статус `HEALTHY` сам по себе не означает увеличение FPS или уменьшение потребления памяти.
