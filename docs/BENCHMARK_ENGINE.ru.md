# Benchmark Engine

Первая версия Benchmark Engine предназначена для воспроизводимых локальных замеров «до/после». Она использует уже имеющиеся окна измерений render-call, тика клиента и интегрированного сервера. Движок не автоматизирует игровой процесс и не обещает универсальный прирост FPS.

## Протокол замера

Каждый запуск следует фиксированному протоколу:

1. Выбери один из шести сценариев в панели управления.
2. По возможности сохраняй неизменными мир, камеру, положение игрока, количество сущностей и графические настройки.
3. Прогрев длится 10 секунд. Эти выборки не попадают в статистику.
4. Измерение длится 30 секунд. Панель показывает оставшееся время и количество собранных выборок.
5. Результат сохраняется локально в версионируемый JSON-файл.

Результат считается неполным, если собрано меньше 30 выборок render-call или меньше 10 выборок client tick. Для сценариев, которым нужен интегрированный сервер, требуется ещё не менее 10 выборок server tick. Неполный результат можно просмотреть, но нельзя сохранить как baseline.

## Сценарии

- `MENU_IDLE` — простой в главном меню.
- `STABLE_SCENE` — стабильная сцена с фиксированными камерой и положением.
- `ENTITY_HEAVY` — подготовленная сцена с большим количеством сущностей.
- `CHUNK_TRAVERSAL` — повторяемый маршрут через загруженные или генерируемые чанки.
- `RESOURCE_RELOAD` — перезагрузка ресурсов, запущенная пользователем.
- `INTEGRATED_SERVER_LOAD` — контролируемая нагрузка в одиночной игре с тиками сервера.

Это инструкции для человека, который проводит тест. Fiximizer не перемещает игрока, не изменяет мир, не создаёт сущности и не запускает перезагрузку ресурсов самостоятельно.

## Метрики

Для каждого вида измерений используется ограниченный кольцевой буфер (по умолчанию 8 192 выборки). Результат содержит количество выборок, число перезаписанных выборок, среднее, стандартное отклонение, минимум, максимум и перцентили p50/p95/p99 по методу ближайшего ранга.

- **Render-call** — время по настенным часам вокруг callback кадра клиента. Это не прямое измерение исполнения GPU или фактической частоты отображаемых кадров.
- **Client tick** — время по настенным часам вокруг callback тика клиента.
- **Integrated-server tick** — время по настенным часам вокруг тика логического сервера, наблюдаемого клиентской частью в одиночной игре. Внутренние тики удалённого выделенного сервера не измеряются.

Для запуска также сохраняются снимки runtime до и после окна измерений: использованная/выделенная/максимальная heap-память, количество потоков, CPU-показания при поддержке JVM, накопительные счётчик и время GC при доступности, счётчики планировщика Fiximizer, состояние JFR и уже опубликованная телеметрия GPU. В этой версии CPU и GPU не усредняются за период. Отсутствующие значения остаются недоступными (например, `-1` в числовых полях), а не выдаются за измеренный ноль.

## Сопоставимость и baseline

Манифест среды записывает версии Minecraft, NeoForge, Fiximizer и Java; ОС и архитектуру; число процессоров; максимальный heap JVM; render/simulation distance; профиль оптимизации и отпечаток настроек.

ID и версии сторонних модов сортируются и хешируются. Исходный список модов в результат не записывается. Идентификаторы игрока, название/путь мира, адрес сервера, чат и содержимое сетевых пакетов не собираются.

Baseline хранится отдельно для каждого сценария и отпечатка совместимой среды в `logs/fiximizer/benchmarks`. Отпечаток включает сценарий, Minecraft/NeoForge/Java, оборудование, стороннюю сборку модов и важные настройки. Версия Fiximizer намеренно не входит в отпечаток: это позволяет сравнивать разные сборки самого Fiximizer, если остальные условия совпадают.

Сравнение отклоняется, если различаются версия схемы, сценарий или отпечаток среды, либо хотя бы один запуск неполный. Отрицательная разница p95 означает, что p95 кандидата ниже для конкретной метрики; это не доказывает улучшение во всех игровых сценариях.

## Файлы и хранение

- `run-<id>.json` — сохранённый запуск.
- `baseline-<scenario>-<fingerprint>.json` — baseline для одного совместимого сценария и среды.

Репозиторий хранит до 40 последних файлов запусков. Baseline хранятся отдельно. JSON записывается через временный файл с атомарной заменой там, где это поддерживает файловая система. API репозитория также поддерживает импорт валидного JSON-запуска как baseline и экспорт выбранного документа запуска или baseline.

Все файлы остаются локально. Автоматической отправки данных или телеметрии нет.

## Текущий объём и ограничения

Эта версия измеряет wall-clock длительность событий и снимки runtime до/после теста. Она пока не агрегирует CPU- или allocation-выборки JFR в результат бенчмарка, не измеряет MSPT/TPS удалённого сервера, независимый RTT и не автоматизирует точные игровые сценарии. Для выводов используй одинаковую ручную процедуру для baseline и candidate и повторяй тесты.
